Decision Models

What happens if we stop asking foundation models to generate an answer and instead ask them to make a decision?

Jev, OpenAI Decisions API, and the emerging “System One” model pattern.

Internal discussion 1
The starting observation

LLMs are surprisingly expensive decision engines

What the application needs

route = "fraud" risk = 0.82 allow_action = false

Software ultimately needs a bounded value it can branch on.

What an LLM naturally produces

"Based on the information provided, this appears most likely to be a fraud-related request because..."

We then parse the generated language back into a decision.

The decision-model thesis: language generation may be unnecessary work when the output space is already known.

Intuition 4
Important nuance

Probably more than embedding similarity

A tempting interpretation is:

Encode state
↔
Encode options
→
Similarity

That is technically possible — and resembles retrieval / bi-encoder classification — but the available evidence around Jev suggests something richer.

Independent scoring

score(A) = F(state, A) score(B) = F(state, B) score(C) = F(state, C)

Candidates do not interact.

Listwise scoring

scores = F(state, question, [A, B, C]) → [.72, .18, .10]

The candidate set itself becomes part of the decision context.

Independent probing of Jev has reported option-set and option-order effects, which are more consistent with joint/listwise evaluation than simple independent embedding similarity.

Jev documentation says multiple questions can share the same state and are evaluated independently. This creates a natural opportunity to reuse the expensive representation of the state.

Exact Jev architecture remains proprietary. Shared KV-prefix / parallel branch interpretations come from external probing and should be treated as informed hypotheses rather than confirmed architecture.

Architecture intuition 6
Why this could matter

Generation has a structural cost

Latency

Autoregressive generation is sequential:

t₁ → t₂ → t₃ → ... → tₙ

A bounded decision may require only one scoring computation.

Type safety

If the output space is:

{A, B, C}

the model cannot suddenly return:

"It depends..."

Probability

The useful output may not be the winner.

A = .51 B = .47 C = .02

Uncertainty itself becomes part of application logic.

Why decision models? 7
Calibration

The probability may be more important than the prediction

If a model says “80% confident”, can we expect it to be correct roughly 80% of the time?

Accuracy

100 decisions 85 correct accuracy = 85%

Tells us how often the model wins.

Calibration

Predictions around 0.8 confidence Observed accuracy ≈ 0.8

Tells us whether uncertainty can be trusted.

This enables a different automation pattern: act when confident, escalate when uncertain.

Jev explicitly positions calibrated decisions as a training objective through its RLCD approach. Independent evaluation has also found useful selective-prediction behavior, although calibration remains workload-dependent.

Calibration 8
A subtle but important correction

“Cannot hallucinate” does not mean “cannot be wrong”

What bounded output solves

  • Invalid output types
  • Unexpected free-form answers
  • Parsing failures
  • Invented categories

What it does not solve

  • Wrong classification
  • Distribution shift
  • Badly specified options
  • Misleading confidence
  • Missing domain knowledge
A decision model can return a perfectly valid but completely wrong value.

The reliability problem therefore moves from “can I parse the answer?” toward “when should I trust the answer?”

Timeline 11
The most interesting technical clue

OpenAI reused GPT-6 Luna

OpenAI's first Decisions implementation was described as using existing GPT-6 Luna weights rather than a newly trained decision foundation model.

Normal Luna

representation ↓ vocabulary logits ↓ next token ↓ next token ↓ next token ↓ text

Decisions

representation ↓ bounded output constraint ↓ candidate scoring ↓ probability distribution ↓ decision
This suggests that at least some “decision-model” behavior can be obtained by changing how an existing foundation model is used at inference time.
OpenAI Decisions 12
The deeper question

New model architecture — or new readout paradigm?

Hypothesis A

Foundation models already contain the necessary representation.

Language generation is simply one possible readout.

foundation model ↓ representation ↓ decision head

OpenAI Decisions v1 points in this direction.

Hypothesis B

Training specifically for decisions changes the representation itself.

Calibration and decision quality may require specialized training.

decision training ↓ different representation ↓ better calibrated decisions

Jev's RLCD thesis points in this direction.

These hypotheses are not mutually exclusive. The interesting question is how much value comes from each layer.

Where this fits

System One + System Two

System One

Fast, bounded judgment.

  • classification
  • routing
  • scoring
  • verification
  • guardrails
  • risk estimation
state → decision → probability

System Two

Open-ended reasoning and generation.

  • analysis
  • planning
  • explanation
  • code generation
  • complex tool use
  • novel problem solving
state → reasoning → generated output
The interesting architecture may not be decision models instead of LLMs, but decision models around and between LLM calls.

Is “decision model” actually a new model category?

Generative LLM Traditional classifier Decision model
Output Open-ended tokens Fixed labels Runtime-defined bounded choices
Task flexibility Very high Low High within bounded decisions
Task-specific training Usually unnecessary Usually required Potentially unnecessary

Category 16
What we know vs what we infer

Keep the epistemology clean

Known

  • Jev exposes bounded typed decisions.
  • It returns probability distributions.
  • Questions can share state.
  • TypeSafe describes specialized RLCD training.
  • OpenAI Decisions v1 reused Luna weights.

Strong inference

  • Removing autoregressive decoding explains much of the latency advantage.
  • Shared state representation can make multiple decisions cheap.
  • Candidate-set interaction likely matters for Jev.

Unknown

  • Exact Jev architecture
  • Exact RLCD objective
  • How much calibration comes from training vs post-processing
  • Whether specialized representations are essential
Evidence 17
Discussion

Questions worth debating

1. Is a decision model fundamentally a new model — or mostly a new inference/readout mechanism?
2. Is calibration actually the key innovation, rather than speed or structured output?
3. Does bounded output genuinely reduce hallucination, or merely move the reliability problem elsewhere?
4. If foundation models already contain rich world representations, how many other useful “heads” besides language generation are we underusing?
5. Should future agent architectures explicitly separate fast judgment from expensive reasoning?
Discussion 18
Takeaway

Maybe the model doesn't always need to talk.

For many AI systems, the useful primitive may be:

state ↓ bounded question ↓ probability distribution ↓ policy / action

Jev made that idea explicit. OpenAI's rapid Decisions API response suggests the pattern may be broader than one model or one vendor.
